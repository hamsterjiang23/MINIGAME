## 对本游戏的结论

此库适合观察如何把检查条件、角色事件、逐日变化和结局组织成可追踪说明。
它是攻略网站，既没有我们的游戏实现，也不能证明参考游戏的全部内部规则。
对本游戏最值得讨论的是“表征具有其他成因，检查者仍可能错误裁决”的信息结构。
我们只写原创分析并引用来源，不复制攻略正文、人物素材或网站图像到本游戏。

## 四种借鉴分类

| 分类 | 本库对应内容 | 我们的处理 |

## 如何转为本游戏的原创研究

1. 从我们的 Wiki 收集检测器能够观察什么、不能判断什么，保持来源口径。
2. 按每位病人、每一天整理玩家可见信息、背景事实及可做处置。
3. 对同一情绪表现列出本游戏已写明的多种原因，不擅自补造罪行或心理诊断。
4. 将普通会谈、特殊会谈、治疗阶段和处置反应连接到各自来源文档。
5. 记录某次处置对下一日患者是否出现及剧情变化的影响。
6. 将结局登记为“触发事实、判定时点、依赖状态、待定项”，避免误把插曲都算正式结局。
7. 以自己的资料制作测试矩阵，检查可见线索与机构裁决之间的叙事关系。
8. 若规则未定，将空项送回 open-questions，不因参考攻略有规则而自动采用。

此流程产生研究与内容设计材料；不会自动新增原游戏中的身体检查、饮料、地下室或访客系统。
我们的主 Wiki 范围仍是三天、五位病人、三种结局，不采用参考攻略的十四天规模。
来源中出现的“电视判据不可靠”等描述属于攻略作者对另一游戏的解读，不是我们的正式设定。

## 可借鉴的表达方式

E02 用日期标明首次 / 再次检查，明确哪些检查不能重复与失败后果。
我们可以原创表达晨检、患者治疗阶段和次日事件，让设计者知道何时发生变化。
E03 将身体表征与道具 / 行为引起的变化关联，说明可见线索和真相不一定一一对应。
本游戏应围绕既有“情绪检测不能裁定善恶”的主题，用会谈和治疗变化表达这一局限。

E04 将完整流程结束的结局与途中事件区分；可启发我们明确普通结束、神父事件与配额失败的时点。
但我们的结局条件仍有缺口，不能直接套用参考游戏的条件或优先级。
E05 提到人物、物品随机及个人剧情，这些是研究对象，不自动要求我们实现随机患者。

## 建议的研究输出结构

| 对象 | 推荐记录 | 用途 |
| --- | --- | --- |
| 检测线索 | 可见表现、已知成因、资料出处、未定解释 | 保持主题与证据可追踪 |
| 每日角色变化 | 日期、会谈入口、治疗阶段、下一日去留 | 对齐三天内容量 |
| 处置 | 允许时机、反应、配额影响、次日影响 | 连接叙事与操作机制 |
| 结局 | 触发记录、判断时点、冲突 / 未定条件 | 编写可重复验证的路径 |
| 知识状态 | 玩家已知事实、已出现线索、病人披露条件 | 避免无依据的全知叙事 |

这里描述的是本游戏应整理的信息，不建议把本攻略数据库作为内容来源导入。
尤其外交官知道什么、神父被释放后的时间、第三次治疗的结果均应以我们的 docs 为准。

## Unity 2022.3 与迁移成本

E01 明确项目为 Next.js / React / MDX 网站，其版本不代表任何 Unity 支持范围。
站点路由、网页组件与索引不能直接解决 Unity 会谈或病人状态管理。
如果只借鉴文档组织，成本是内容表和链接规范，不需要安装网站运行依赖。
如果未来做游戏内档案，应原创实现 UI 与状态读取，而不是移植整站。
本次未安装依赖、未构建站点、未核验攻略描述与实际原游戏版本的一致性。

## 许可与内容边界

E06 为 File to Downloader 自定义许可，不能写成 MIT 或通常意义上的无限制开源许可。
许可限制其内容成为商业核心价值，并禁止模型训练、微调、蒸馏等相关使用。
分发修改内容还要求保留来源、版权及许可信息；其他未授权范围需要另行许可。
这些是本地许可文本的条款记录，不替代对具体使用方式的法律判断。
默认只提供原创研究、短出处说明和证据链接，不复制攻略正文、截图、人物图或网站素材。
原游戏图像和品牌的权利也不能因攻略站许可而推定获得。
本研究不创建训练数据，不把攻略喂入角色模型，不用于模型训练或蒸馏。

## 后续验证场景

- 每项借鉴结论链接到原攻略位置，同时明确它属于另一游戏的描述。
- 我们的机制表中每条事实仍能追溯到自己的 Wiki 文档。
- 检测表征与道德裁决保持设计中的区别，不把参考身体征兆当确定事实。
- 正式结局与日间事件分类清楚，没有引入第四种占位结局。
- 三天内容量未被十四天攻略、随机访客或额外道具扩大。
- 神父、外交官及治疗次数冲突保留待定项，没有用攻略自行补写。
- 本地文档与工程没有复制攻略正文、人物图或截图素材。
- 若后续要使用原站内容，先逐项核对自定义许可与素材权利，再决定使用范围。
