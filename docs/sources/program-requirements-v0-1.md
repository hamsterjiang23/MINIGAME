## 内容概述

第一人称交互、日循环与监控审判界面的程序需求。

## 设计重点

无肢体、无跳跃、E交互；3D场景与2D人物物件；隐藏释放键、治疗键、净化键；配额、独立信任值、多轮汇合对白。

## 程序需求v0.1

#### 1. 第一人称基础框架

- 第一人称
- 无玩家模型，不要看到玩家肢体
- 无跳跃
- 按E可以与场景/物件交互，物件交互弹出文本（先用临时文本），与场景交互涉及摄像机移动与2d视角转换


> 画板 `FfORwsEwwhfH9cbHbpQc8OMsnWe`：已读取，文本与连线详见下方画板补充。


- 2D 与 3D 混合：场景 3D，人物与物件 2D。参考《寻找伪人》——本质只建了一条走廊，其余房间全是 2D 资产
- 支持交互时的音效

#### 2. 日循环状态机

- 状态：敲门 → 对话 → 工作 → 睡眠 →做梦、醒来
- 支持玩家不同状态下的音乐切换
- 支持不同数值的记录，比如根据选择记录玩家疯狂值，结算后影响第二天出现的选择

#### 3. 审判系统

- 病人单次会面流程：播放立绘与对话 →玩家做出对话选择，重复对话→ 等待玩家按键 → 记录判定结果
- 纯2d界面，参考把脸贴到下图上的效果。如何从3d的场景进入一个可交互的独立2d界面，这是需要解决的技术难点，我目前的想法是这个过程通过摄像机移动来包装，先通过一个预先设计好的开机界面隐藏加载，然后再进真正的操作界面，但是两者之间的过渡顺滑、以及2d3d交互的改变需要解决。

![图片展示了一台老式电脑显示器，屏幕上显示着绿色的代码和文字。屏幕上方有“Bit 5 + 2 + 7 + 0 UCP - UPC - UST - Kanal0”等信息，下方提示“Bitte aktuelle Uhrzeit in der Form HH:MM eingeben!”（请输入当前时间格式为HH:MM）。屏幕底部有多个文件夹图标及名称，如“BUS”“COM”“US”等。该图片与文档中审判系统的内容相关，可能是系统界面或操作提示示例。](../assets/image-GbgYbfa14oc45ZxE1c5cZBYenxf.png)

- 三个按键：

  - 隐藏绿键「释放」：代价大，释放要求高
  - 黄键「治疗」：有危险但可挽救；病人会表现痛苦
  - 红键「净化」：终极处理，该人直接消失
- 疗愈配额：每日右上角数字，表示玩家需要净化的人数，每次净化后数字减一
- 多分支对话结构

1. 每角色每日普通对话计划4–5轮（有的角色可能有差异）
2. 每轮角色说1–4句话，玩家从最多4个回复中选1句
3. 不同回复选择引出不同角色对白，再自然收束到相同结尾，共用下一套回复
4. 【信任值】隐藏（eg 0-100），每个病人独立维护。回应会增加或减少信任（存在病人的信任无限大或负一万，也有可能某些选项
5. 达到信任值阈值（eg 50，根据角色、角色出现天数不同）且普通对话结束后，进入1轮独有的特殊对白与回答选项，不再汇合普通路线；特殊轮的回应拟具有更大信任影响（+的更多/-的更多）也许具有关键信息透露、关键剧情抉择。
6. 释放/净化/治疗操作只能在对话结束之后选择，操作后跳转到对应特殊对话，并花屏结束该病人审判；对话结束后屏幕上会亮起一个灯，有红绿两种状态，绿灯则可以释放，红灯情况下点击释放按钮无效。是否亮灯暂定和信任值相关，每个角色有单独的亮灯阈值
